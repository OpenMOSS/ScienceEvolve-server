**Extension research judgment: sufficient for implementation.** The official
sources cover provider flow, state/PKCE, account selection, token lifecycle,
stable identity, required repository scope and the relevant editor/list
interaction patterns. The chosen design keeps credential authority on the
server, binds one account before repository mutation and reuses the existing
canvas inspector/draft model. No unresolved product choice blocks this
extension; live provider login still requires deployment OAuth configuration
and must not be claimed from mocked tests.

## Decisions rejected after comparison

- A generic nested-team model is rejected because P04 forbids nesting.
- A user-selected or fixed manager is rejected because P06 derives the temporary leader from the caller/route.
